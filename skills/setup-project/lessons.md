# Lessons

Read this before changing code. The nightly review writes it. A working
session reads it and does not promote its own lesson.

Each lesson is a rule, then why, then the evidence. Seen counts the days a
review found it. A lesson seen on 3 separate days moves into `docs/rules/`.
A miss that shipped broken to a user the same day is written into `docs/rules/`
that night and does not wait for 3.

```text
**A rule in one sentence.**
- Which commit, issue, or session, and what it cost.
- The commit that fixed it.
- Done right: a commit that got this right, when there is one.
- Seen N× (YYYY-MM-DD).
```

The review looks for three things only: fixed and then fixed again, what
should not have merged, and what was verified too thinly. Taste and whether a
feature should exist are the maintainer's.
