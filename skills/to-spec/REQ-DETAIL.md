# REQ 详细度

写 Requirements 前加载。目标：spec 能独立实施，少回查 PRD；**每条示例、文案、边界值都来自来源**（PRD / 问卷 / 对话 / 现有代码），绝不编造。

## 选档

从高往低判，命中即停：

| 档 | 任一命中 |
| --- | --- |
| 高 | ≥3 个模块或跨系统数据流；金额 / 数量 / 时间计算（计价、折扣、额度、统计窗口、补差）；≥6 个状态或有定时驱动的状态迁移；用户要求"可直接 implement 的 spec" |
| 中 | 2 个模块；3–5 个状态 |
| 低 | 以上都不命中（单模块 CRUD、纯样式调整） |

用一行说明选了哪一档、命中了哪条，然后直接写，不等待回复。用户指定档位时以用户为准。

## 各档要求

| REQ 类型 | 高 | 中 | 低 |
| --- | --- | --- | --- |
| 算法（计价、计费、窗口） | 公式 + ≥3 组示例（输入 → 计算过程 → 输出），至少一组是边界输入（0、上限、负数）；精度和舍入规则写明 | 公式 + 1 组关键路径示例 | 公式 |
| 文案（错误提示、确认弹窗、通知、按钮跳转） | ≤5 行的文案逐字复制，包含标点；通知写明渠道、接收人、按钮跳转；长文案引用 PRD 章节 | 错误提示和弹窗逐字复制，其余可引用 | 引用 PRD 章节 |
| 判定（时间窗口、状态切换、权限、上下限） | 每个分支 ≥1 个边界用例（输入 → 结果）；时间判定包含 0 天和最后一天；数量判定包含 0、上限、上限+1 | 主要分支各 1 个用例 | 列出分支 |
| UI 交互 | 状态集合按 [PRD-AUTHORITY.md](PRD-AUTHORITY.md) §2 的 pin row；写清切换条件、禁用和隐藏规则 | 关键状态 | 一句描述 |
| 数据结构 | 字段约束（必填、长度、精度、唯一）、契约意图、存量迁移规则；不写 DDL 或 JSON 片段 | 同左，只写变更字段 | 一句描述 |

样式数值（色值、尺寸、圆角、动效）不放在 spec 里：spec 只给出 `Delivery design pin` 和 pin row，具体数值在实现阶段按 [UI.md](../implement/UI.md) 从设计源读取。

## 来源缺口

分两类处理：

- **产品事实缺失**：精度、舍入、文案、边界的判定结果在来源里找不到。PRD 来源时，Inventory 对应行的 `REQ` 列填 `HITL` 并写明缺什么，走 [PRD-AUTHORITY.md](PRD-AUTHORITY.md) §2 的 fail-closed；非 PRD 来源时写进 Further Notes。两种情况 spec 都不能 `accepted`。
- **机械推算**：来源已经给了公式和规则，示例只是把它代入计算。标注"推算自 §x"，作为说明性示例保留，不算新的产品事实，也不进 Accepted PRD deltas。

## 自查

发布前逐条检查：本档要求的每一项，要么有来源支撑或标了"推算自"，要么已经作为产品事实缺口记录。
